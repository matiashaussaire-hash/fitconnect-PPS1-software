# Modelos de Proceso

| Modelo      | Ventaja                                                                 | Desventaja                                                        |
| ------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Cascada      | Permite una planificación clara y ordenada del proyecto desde el inicio. | Es poco flexible frente a cambios en requisitos o funcionalidades. |
| En V         | Facilita realizar pruebas rigurosas en cada etapa del desarrollo.        | Requiere requisitos muy bien definidos desde el principio.         |
| Incremental  | Permite lanzar FitConnect por partes y obtener feedback temprano.        | La integración entre módulos puede volverse compleja.              |
| Iterativo    | Permite mejorar continuamente la aplicación según opiniones de usuarios. | Puede aumentar el tiempo total de desarrollo.                      |
| Prototipos   | Ayuda a validar ideas e interfaces rápidamente.                          | Los usuarios pueden confundir el prototipo con el producto final.  |
| Espiral      | Permite detectar y reducir riesgos desde etapas tempranas.               | Es más complejo y costoso de gestionar.                            |
| Scrum / XP   | Permite adaptarse rápidamente a cambios y trabajar en ciclos cortos.     | Requiere mucha organización y comunicación constante.              |

## Modelo recomendado

El modelo recomendado para FitConnect es Scrum/XP porque permite desarrollar la aplicación de forma ágil, adaptarse a cambios y mejorar continuamente según el feedback de usuarios y entrenadores.

## Factores que influyeron en la decisión

- Requisitos cambiantes.
- Necesidad de feedback constante.
- Gran cantidad de funcionalidades.
- Importancia de la experiencia de usuario.
- Posibilidad de lanzar versiones incrementales.
